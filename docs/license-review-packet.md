## 1. 実現したい利用方針（案）

| 利用形態 | 方針 |
| --- | --- |
| 独自コードを閲覧・学習する | 許可 |
| 個人・非商用で独自コードを実行・改変する | 許可 |
| 条件を守った非商用の再配布 | 許可 |
| FabCAD独自コードを企業・事業の社内業務へ組み込む | 別途書面許諾 |
| 独自コードを使った外部向けWebサービス（無料クローンを含む） | 別途書面許諾 |
| **公式FabCAD上で作ったモデル・SVG・DXF・STL・STEPなど** | 業務利用・販売も許可。成果物の権利は利用者に帰属 |

**ソースが公開されていてもOSI承認のOSSではありません。**
第三者製のMIT/LGPL/OFL等のライセンスは、FabCADの独自コード条件では変更できません。

## 3. 法的レビューで回答すべき論点

- [ ] **許諾者の確定**: 個人・法人の正式名称と著作権表示を決める。GitHub組織名だけを権利者とみなさない。職務著作・業務委託・第三者コード利用の契約上の権利も確認する。
- [ ] **社内評価の扱い**: 非営利の検証、企業の試用、学校・大学の利用が意図せず禁止されていないか。企業内評価を許可する場合は範囲・期間・再配布条件を明示する。
- [ ] **無料ホスティング禁止**: 非商用の派生版を無償で第三者向けにホスティングすることまで禁止する方針が、想定する普及・協業戦略に適切か。
- [ ] **LGPL-2.1第6条との整合**: 独自LICENSEの自己利用改変・デバッグ目的のリバースエンジニアリング例外が十分か。対象ライブラリの正確な対応ソース・ビルド資材・利用者による改変ライブラリ使用方法が必要な形で提供されているか。
- [ ] **Third-Party Materialsの切り分け**: 独自ライセンスが第三者MIT・LGPL・OFL・FTL等の許諾を狭めていないか。リンクするネイティブライブラリの原文・著作権表示に不足がないか。
- [ ] **特許、保証、解除、準拠法**: 特許許諾を明示しない影響、免責範囲、30日是正条項、日本法準拠、既取得コピーの権利存続の整合性。
- [ ] **成果物の商用自由**: 公式Webサービスで作ったモデル・加工データを利用者が販売でき、第三者素材の権利にだけ留保を置く設計が利用規約と矛盾しないか。
- [ ] **将来の外部貢献**: 商用の別契約で再ライセンスするためにCLA等が必要か。DCOだけでは商用再許諾の包括的な権利付与にならない可能性がある。
